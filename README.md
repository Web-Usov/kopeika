# Копейка 🪙

Telegram Mini App для учёта общих трат в компании: группы, траты с делением поровну, долями или точными суммами, балансы, минимальный план переводов и уведомления от бота.

## Как устроено

```
web/      Mini App: React + Vite + TypeScript, telegram-web-app.js
server/   API (Hono) + бот (grammY, long polling) + SQLite (встроенный node:sqlite)
shared/   Расчёты: деление суммы, балансы, план переводов (используются и сервером, и фронтом)
```

- Деньги хранятся целыми числами в копейках/центах.
- Пользователь авторизуется подписью Telegram `initData` (заголовок `Authorization: tma <initData>`), сервер проверяет её токеном бота.
- Приглашение — ссылка `t.me/<бот>/<short_name>?startapp=<код>`. По ней Mini App открывает экран вступления, где можно выбрать себя среди участников, добавленных по имени.
- В продакшене один контейнер: Node отдаёт статику фронта, API на `/api` и запускает бота.

## Локальная разработка

```bash
npm install
cp .env.example .env     # заполнить; для работы в браузере добавить DEV_AUTH=1 и BOT_POLLING=0
npm run dev:server       # API на :3000
npm run dev:web          # Mini App на :5173 (проксирует /api на :3000)
```

В обычном браузере открывай `http://localhost:5173/?dev=1`, второй пользователь — `?dev=2`, приглашение — `?dev=2&startapp=<код>`.

Git-хук pre-push ставится сам при `npm install` и гоняет `npm run check` перед каждым пушем. В крайнем случае обойти можно через `git push --no-verify`.

Чтобы проверить внутри Telegram, нужен HTTPS: например `cloudflared tunnel --url http://localhost:5173` и временно указать этот адрес в @BotFather (лучше на отдельном тестовом боте).

```bash
npm test          # тесты расчётов и проверки initData
npm run typecheck
```

## Деплой

Образ собирается GitHub Actions при каждом пуше в `main` и публикуется в GitHub Container Registry (amd64 и arm64):

- `ghcr.io/web-usov/kopeika:latest` — последняя версия из `main`;
- `ghcr.io/web-usov/kopeika:sha-<коммит>` — конкретная сборка, для отката;
- `ghcr.io/web-usov/kopeika:1.2.3` — если поставить git-тег `v1.2.3`.

```bash
cp .env.example .env   # BOT_TOKEN, APP_URL, APP_SHORT_NAME
docker compose pull && docker compose up -d
```

В Portainer можно вставить [docker-compose.yml](docker-compose.yml) как stack, а переменные из `.env.example` задать в Environment variables. Обновление: pull + redeploy стека.

Собрать образ локально: `docker build -t kopeika .`

Контейнер слушает порт `3000`, база лежит в volume `kopeika-data` (`/data/kopeika.db`). HTTPS и домен настраиваются в Traefik.

Проверка: `GET /healthz` → `ok`.

Конфигурация проверяется при старте: числовая переменная с неверным значением (`PORT`, `RATE_LIMIT_PER_MIN`, `BACKUP_KEEP`, `CHAT_DIGEST_HOUR` и т. д.) — сервер не запускается и называет переменную в ошибке. Образ собран с `NODE_ENV=production`, и с `DEV_AUTH=1` он тоже откажется стартовать; флаг `ALLOW_DEV_AUTH_IN_PRODUCTION=1` нужен только smoke-тестам в CI, в проде его задавать нельзя. HTML отдаётся с `Content-Security-Policy` (в том числе `frame-ancestors` только для Telegram). Базовый образ в `Dockerfile` закреплён по digest; обновлять осознанно, через PR.

Сервер стартует, даже если Telegram недоступен: бот подключается в фоне и повторяет попытки (5 → 10 → 30 → 60 с, дальше раз в минуту), пока не получится. Пока бота нет, уведомления, экспорт и ссылки-приглашения с именем бота отключены. Если `api.telegram.org` заблокирован или медленный, задайте `TELEGRAM_API_ROOT` — адрес прокси или собственного Bot API server (например `http://bot-api-proxy:8081`). `TELEGRAM_TIMEOUT_SEC` — таймаут запросов к Telegram в секундах (по умолчанию 20).

### Бэкапы

Раз в сутки (и при старте, если сегодняшнего бэкапа ещё нет) сервер делает консистентную копию базы в `/data/backups/kopeika-YYYY-MM-DD.db` — внутри того же volume `kopeika-data`. Хранятся последние `BACKUP_KEEP` файлов (по умолчанию 14), папка меняется через `BACKUP_DIR`. Время от времени копируйте их и за пределы сервера.

Восстановление: остановить контейнер, скопировать нужный бэкап поверх `/data/kopeika.db` (удалив рядом `kopeika.db-wal` и `kopeika.db-shm`, если есть), запустить контейнер.

### Статистика использования

Сервер ведёт обезличенные дневные счётчики событий (группы, траты, вступления, экспорт и т. д.) в таблице `stats_daily` — без id пользователей и групп. Активные пользователи считаются на лету по `users.updated_at`. Владелец видит отчёт командой `/stats` в личке с ботом: задайте свой Telegram id в `ADMIN_USER_IDS` (через запятую). Остальным команда не отвечает; в меню команд её нет.

### Чеки

Распознавание чека по фото (`POST /api/groups/:id/receipts/parse`) работает через Anthropic API. Чтобы включить: задайте `ANTHROPIC_API_KEY` (ключ ваш, не коммитьте). Пока ключ пуст, функция выключена: эндпоинт отвечает 503, а `GET /api/me` отдаёт `receiptsEnabled: false`.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `ANTHROPIC_API_KEY` | пусто (выключено) | ключ API; не логируется и не отдаётся клиенту |
| `ANTHROPIC_BASE_URL` | пусто | адрес прокси или шлюза до API (необязательно) |
| `RECEIPTS_MODEL` | `claude-haiku-5-5` | модель, читающая чек |
| `RECEIPTS_FALLBACK_MODEL` | пусто (без каскада) | модель посильнее; её один раз спрашивают, если позиции не сходятся с итогом |
| `RECEIPTS_TIMEOUT_SEC` | `30` | таймаут одного запроса к провайдеру |

Фото принимается как JSON `{ "image": "<base64>", "mediaType": "image/jpeg|image/webp|image/png" }` (до ~3 МБ тела; клиент заранее уменьшает снимок) и живёт только в памяти на время запроса: на диск и в логи не попадает. Ответ — черновик `{ merchant, date, currency, items[{id, name, quantity?, amount}], adjustments[{kind, label, amount, percent}], total, mismatch, confidence, warnings }`; суммы в минимальных единицах валюты чека, `mismatch: true`, если позиции с надбавками не сходятся с напечатанным итогом. Сервер Anthropic должен быть доступен с сервера приложения. Перед первым сканом приложение спрашивает согласие (`users.receipt_consent_at`). В демо-группе чеки выключены.

**Закрытая бета** (`server/src/receipts/access.ts`, #125). По умолчанию (`RECEIPTS_BETA=1`) группа может разбирать чеки только после одобрения владельцем; сервер отвечает 403 на `POST /api/groups/:id/receipts/parse`, даже если клиент обошёл интерфейс. Участник нажимает «Разобрать чек · бета» → «Запросить доступ» (`POST /api/groups/:id/receipts/access-request`: повтор при висящем запросе не создаёт дубль, после отказа — не чаще раза в сутки, демо-группа — 409). Каждому из `ADMIN_USER_IDS` бот шлёт в личку карточку запроса с кнопками «✅ Открыть доступ» / «❌ Отклонить» (callback `rb:a:<id>` / `rb:r:<id>`); решение обновляет карточку и пишет запросившему. Одобрение — право `receipts_beta`: работают пробные `RECEIPTS_GROUP_TRIAL_MONTHLY` разборов и общий потолок. Команды владельца в личке: `/beta <код-приглашения>` — открыть доступ без запроса, `/requests` — список ожидающих запросов, `/grant` — снять лимит (и открыть доступ), `/revoke` — убрать оба права. Если `ADMIN_USER_IDS` пуст, запрос сохраняется, а в логах предупреждение.

**Лимиты и учёт** (`server/src/receipts/limits.ts`, #102). Группе без права `receipts` доступно `RECEIPTS_GROUP_TRIAL_MONTHLY` пробных сканов в календарный месяц (по времени сервера); право снимает этот лимит. Владелец (`ADMIN_USER_IDS`) выдаёт и отзывает право в личке с ботом: `/grant <код-приглашения> [дней]` и `/revoke <код-приглашения>`. Расход на все сканы ограничен общим месячным бюджетом: при 80% владелец получает сообщение, при 100% сканирование приостанавливается. На каждый скан в `receipt_scans` пишутся только группа, модель, токены и стоимость, без фото и содержимого чека.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `RECEIPTS_BETA` | `1` | закрытая бета: чеки доступны только одобренным группам; `0` — открыто всем (с пробным лимитом и общим потолком) |
| `RECEIPTS_GROUP_TRIAL_MONTHLY` | `5` | пробных сканов на группу в месяц, пока у группы нет права `receipts` |
| `RECEIPTS_USER_PER_MIN` | `3` | запросов распознавания на пользователя в минуту |
| `RECEIPTS_GLOBAL_MONTHLY_USD` | `10` | общий потолок расхода в месяц, $ |
| `RECEIPTS_PRICE_IN_USD_PER_M` | `0.1` | цена входных токенов, $ за 1 млн (для расчёта стоимости; одна на все модели, при каскаде задайте под свою) |
| `RECEIPTS_PRICE_OUT_USD_PER_M` | `0.5` | цена выходных токенов, $ за 1 млн |

Конфиденциальность: фото уходит в Anthropic только на время запроса и у нас не хранится, позиции не сохраняются, учитывается лишь число сканов и стоимость; при «Удалить мои данные» согласие удаляется, а записи о сканах отвязываются от человека (остаются обезличенно как учёт расхода для месячного бюджета). Перед включением функции в продакшене проверьте, что `shared/privacy.ts` (ru/en) отражает фактическое поведение. Подробности: `docs/specs/receipts.md`.

## Настройка бота в @BotFather

1. `/newbot` → токен в `BOT_TOKEN`.
2. `/newapp` → URL `https://kopeika.usov-home.ru`, short name → в `APP_SHORT_NAME`.
3. При старте сервер сам ставит кнопку меню бота, ведущую на `APP_URL`.
4. **Вручную:** `/mybots` → бот → Bot Settings → Privacy Policy → указать `https://<домен>/privacy`. Страница на двух языках отдаётся самим сервером (`?lang=en` — английская), внутри приложения та же политика открывается по `#/privacy`. Текст политики — `shared/privacy.ts`; менять его нужно вместе с кодом, если меняется то, что мы храним или показываем.

## Удаление данных пользователя

Кнопка «Удалить мои данные» на главном экране вызывает `DELETE /api/me` (код — `server/src/account.ts`, одна транзакция): группы, где пользователь единственный с Telegram, удаляются целиком; из остальных он выходит (становится участником без Telegram, владение передаётся); строка `users`, напоминания и токены привязки чатов удаляются; регулярные траты пользователя ставятся на паузу; трата, записи истории и шаблоны, которые он создал, переходят на служебного «удалённого пользователя» (`users.id = 0`). Из ежедневных бэкапов данные уйдут сами через `BACKUP_KEEP` дней.
