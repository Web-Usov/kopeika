# Копейка 🪙

Telegram Mini App для учёта общих трат в компании: группы, траты с делением поровну, долями или точными суммами, балансы, минимальный план переводов и уведомления от бота.

План и решения владельца — в [docs/roadmap.md](docs/roadmap.md).

## Как устроено

```
web/      Mini App: React + Vite + TypeScript, telegram-web-app.js
server/   API (Hono) + бот (grammY, long polling) + SQLite (встроенный node:sqlite)
shared/   Расчёты: деление суммы, балансы, план переводов (используются и сервером, и фронтом)
```

- Деньги хранятся целыми числами в копейках/центах.
- Пользователь авторизуется подписью Telegram `initData` (заголовок `Authorization: tma <initData>`), сервер проверяет её токеном бота.
- Приглашение — ссылка `t.me/<бот>/<short_name>?startapp=<код>`. По ней Mini App открывает экран вступления, где можно выбрать себя среди участников, добавленных по имени.
- В продакшене один контейнер: Node отдаёт статику фронта, API на `/api` и запускает бота.

## Локальная разработка

```bash
npm install
cp .env.example .env     # заполнить; для работы в браузере добавить DEV_AUTH=1 и BOT_POLLING=0
npm run dev:server       # API на :3000
npm run dev:web          # Mini App на :5173 (проксирует /api на :3000)
```

В обычном браузере открывай `http://localhost:5173/?dev=1`, второй пользователь — `?dev=2`, приглашение — `?dev=2&startapp=<код>`.

Git-хук pre-push ставится сам при `npm install` и гоняет `npm run check` перед каждым пушем. В крайнем случае обойти можно через `git push --no-verify`.

Чтобы проверить внутри Telegram, нужен HTTPS: например `cloudflared tunnel --url http://localhost:5173` и временно указать этот адрес в @BotFather (лучше на отдельном тестовом боте).

```bash
npm test          # тесты расчётов и проверки initData
npm run typecheck
```

## Деплой

Образ собирается GitHub Actions при каждом пуше в `main` и git-теге `v*` и публикуется в GitHub Container Registry (amd64 и arm64):

- `ghcr.io/web-usov/kopeika:latest` — последний релиз (git-тег `v*`); именно его запускает `docker-compose.yml`; пре-релизы `v1.2.3-rc.1` в `:latest` не попадают;
- `ghcr.io/web-usov/kopeika:main` — последняя сборка из `main`, ещё не релиз;
- `ghcr.io/web-usov/kopeika:sha-<коммит>` — конкретная сборка, для отката;
- `ghcr.io/web-usov/kopeika:1.2.3` — релиз с git-тегом `v1.2.3`.

```bash
cp .env.example .env   # BOT_TOKEN, APP_URL, APP_SHORT_NAME и остальное по желанию
docker compose pull && docker compose up -d
```

Все переменные из env-файла попадают в контейнер через `env_file` в [docker-compose.yml](docker-compose.yml): `.env` рядом с compose-файлом (docker compose) и `stack.env` (файл переменных стека в Portainer). Любого из файлов может не быть; если есть оба, `stack.env` приоритетнее. `BOT_TOKEN` обязателен.

В Portainer можно вставить [docker-compose.yml](docker-compose.yml) как stack, а переменные из `.env.example` задать в Environment variables. После добавления или изменения переменных нужен redeploy стека. Обновление: pull + redeploy стека.

Собрать образ локально: `docker build -t kopeika .`

Контейнер слушает порт `3000`, база лежит в volume `kopeika-data` (`/data/kopeika.db`). HTTPS и домен настраиваются в Traefik.

Проверка: `GET /healthz` → `ok`.

Конфигурация проверяется при старте: числовая переменная с неверным значением (`PORT`, `RATE_LIMIT_PER_MIN`, `BACKUP_KEEP`, `CHAT_DIGEST_HOUR` и т. д.) — сервер не запускается и называет переменную в ошибке. Образ собран с `NODE_ENV=production`, и с `DEV_AUTH=1` он тоже откажется стартовать; флаг `ALLOW_DEV_AUTH_IN_PRODUCTION=1` нужен только smoke-тестам в CI, в проде его задавать нельзя. HTML отдаётся с `Content-Security-Policy` (в том числе `frame-ancestors` только для Telegram). Базовый образ в `Dockerfile` закреплён по digest; обновлять осознанно, через PR.

Сервер стартует, даже если Telegram недоступен: бот подключается в фоне и повторяет попытки (5 → 10 → 30 → 60 с, дальше раз в минуту), пока не получится. Пока бота нет, уведомления, экспорт и ссылки-приглашения с именем бота отключены. Если `api.telegram.org` заблокирован или медленный, задайте `TELEGRAM_API_ROOT` — адрес прокси или собственного Bot API server (например `http://bot-api-proxy:8081`). `TELEGRAM_TIMEOUT_SEC` — таймаут запросов к Telegram в секундах (по умолчанию 20).

### Бэкапы

Раз в сутки (и при старте, если сегодняшнего бэкапа ещё нет) сервер делает консистентную копию базы в `/data/backups/kopeika-YYYY-MM-DD.db` — внутри того же volume `kopeika-data`. Хранятся последние `BACKUP_KEEP` файлов (по умолчанию 14), папка меняется через `BACKUP_DIR`. Время от времени копируйте их и за пределы сервера.

Восстановление: остановить контейнер, скопировать нужный бэкап поверх `/data/kopeika.db` (удалив рядом `kopeika.db-wal` и `kopeika.db-shm`, если есть), запустить контейнер.

### Ошибки и мониторинг

Об ошибках владелец узнаёт сам (`server/src/alerts.ts`, #134). Каждому из `ADMIN_USER_IDS` бот шлёт в личку сообщение о необработанной ошибке сервера (5xx из `api.onError`, `unhandledRejection`, `uncaughtException`) и об ошибке в Mini App (окно `error`, `unhandledrejection` и ошибки рендера React; клиент отправляет их на `POST /api/client-errors` — не больше 5 за сессию, без повторов). Одинаковые ошибки (источник + сообщение + первая строка стека) склеиваются: первое сообщение приходит сразу, дальше не чаще раза в час с числом случаев; всего не больше 20 сообщений в час. В тексте нет персональных данных: сообщение, место в коде или маршрут без id и параметров, версия, платформа. `ERROR_ALERTS=0` выключает рассылку (в лог ошибки пишутся всегда); пока бот не готов, оповещение пропускается. Процесс при `uncaughtException` и `unhandledRejection` по-прежнему завершается с кодом 1 (контейнер перезапускается), но сначала до 3 секунд ждёт отправки сообщения.

Сам сервер о своём падении или недоступности сообщить не может, поэтому внешнюю проверку настраивает владелец. Например, в UptimeRobot (или аналоге): новый монитор типа HTTP(s) на `https://<ваш-домен>/healthz` с интервалом 5 минут и ключевым словом `ok`; в «Alert contacts» подключите Telegram (бот UptimeRobot) — он напишет в личку, когда сервис упал и когда поднялся.

### Статистика использования

Сервер ведёт обезличенные дневные счётчики событий (группы, траты, вступления, экспорт и т. д.) в таблице `stats_daily` — без id пользователей и групп. Активные пользователи считаются на лету по `users.updated_at`. Владелец видит отчёт командой `/stats` в личке с ботом: задайте свой Telegram id в `ADMIN_USER_IDS` (через запятую). Остальным команда не отвечает; в меню команд её нет.

В `/stats` есть блок «Воронка групп» за 7 и 30 дней по дате создания группы (демо-группы не считаются; считается на лету из `groups`, `members`, `expenses`): создано; «ожило» — не меньше 2 участников с Telegram и 3 трат (переводы не в счёт); «вернулись на 2-й неделе» — трата или перевод через 7–14 дней после создания, среди групп старше 14 дней (поэтому когорта сдвинута: группы, созданные 14–21 и 14–44 дня назад). Источник вступления считается счётчиками `join.link` (ссылка-приглашение, старые ссылки тоже) и `join.card` (карточка, отправленная в чат: inline-режим и «В чат»). У карточки `startapp` = `<код>-c`; суффикс признаётся только у параметра длиной ровно 14 символов (код всегда 12 символов base64url, `-` в нём бывает), см. `shared/invite.ts`. Клиент отрезает суффикс и передаёт `source` в `POST /api/invite/:code/join`. Каждый понедельник с 9:00 по времени сервера бот присылает этот же отчёт каждому из `ADMIN_USER_IDS` (`server/src/statsWeekly.ts`); `STATS_WEEKLY=0` выключает рассылку. Пока бот не готов, рассылка молча пропускается и повторяется через полчаса; понедельник отмечается в таблице `app_state` до отправки, поэтому перезапуск сервера не даёт дубль.

### Чеки

Распознавание чека по фото (`POST /api/groups/:id/receipts/parse`) работает через Anthropic API или через любой OpenAI-совместимый (OpenRouter, свой vLLM). Чтобы включить: задайте `ANTHROPIC_API_KEY` (ключ ваш, не коммитьте), либо `RECEIPTS_PROVIDER=openrouter` и `OPENROUTER_API_KEY`. Пока ключ выбранного провайдера пуст, функция выключена: эндпоинт отвечает 503, а `GET /api/me` отдаёт `receiptsEnabled: false`.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `ANTHROPIC_API_KEY` | пусто (выключено) | ключ API; не логируется и не отдаётся клиенту |
| `RECEIPTS_PROVIDER` | `anthropic` | `anthropic` или `openrouter` (OpenAI-совместимый API) |
| `OPENROUTER_API_KEY` | пусто (выключено) | ключ OpenRouter (или своего сервера); нужен при `RECEIPTS_PROVIDER=openrouter` |
| `OPENROUTER_BASE_URL` | `https://openrouter.ai/api/v1` | адрес API; для своего vLLM укажите его |
| `OPENROUTER_PROVIDERS` | пусто | через запятую: хостеры OpenRouter, которым разрешено отвечать (`provider.only`) |
| `ANTHROPIC_BASE_URL` | пусто | адрес прокси или шлюза до API (необязательно) |
| `RECEIPTS_MODEL` | `claude-haiku-5-5` (`qwen/qwen3.5-35b-a3b` для openrouter) | модель, читающая чек |
| `RECEIPTS_FALLBACK_MODEL` | Anthropic: пусто (без каскада); openrouter: та же модель | вторая ступень каскада, её один раз спрашивают, если позиции не сходятся с итогом. Для openrouter пусто = та же модель с `RECEIPTS_FALLBACK_REASONING`; имя модели = она; `none` = без каскада |
| `RECEIPTS_REASONING` | `none` | только openrouter: рассуждения первого запроса: `none`, `minimal`, `low`, `medium` или `omit` (поле `reasoning` не отправляется, для моделей без этого параметра). Неизвестное значение = по умолчанию и предупреждение при старте |
| `RECEIPTS_FALLBACK_REASONING` | `low` | только openrouter: рассуждения второй ступени каскада, значения те же |
| `RECEIPTS_TIMEOUT_SEC` | `30` (`45` для openrouter) | таймаут одного запроса к провайдеру |

Фото принимается как JSON `{ "image": "<base64>", "mediaType": "image/jpeg|image/webp|image/png" }` (до ~3 МБ тела; клиент заранее уменьшает снимок) и живёт только в памяти на время запроса: на диск и в логи не попадает. Ответ — черновик `{ merchant, date, currency, items[{id, name, quantity?, amount}], adjustments[{kind, label, amount, percent}], total, mismatch, confidence, warnings }`; суммы в минимальных единицах валюты чека, `mismatch: true`, если позиции с надбавками не сходятся с напечатанным итогом. API выбранного провайдера должен быть доступен с сервера приложения. Перед первым сканом приложение спрашивает согласие (`users.receipt_consent_at`). В демо-группе чеки выключены.

**Закрытая бета** (`server/src/receipts/access.ts`, #125). По умолчанию (`RECEIPTS_BETA=1`) группа может разбирать чеки только после одобрения владельцем; сервер отвечает 403 на `POST /api/groups/:id/receipts/parse`, даже если клиент обошёл интерфейс. Участник нажимает «Разобрать чек · бета» → «Запросить доступ» (`POST /api/groups/:id/receipts/access-request`: повтор при висящем запросе не создаёт дубль, после отказа — не чаще раза в сутки, демо-группа — 409). Каждому из `ADMIN_USER_IDS` бот шлёт в личку карточку запроса с кнопками «✅ Открыть доступ» / «❌ Отклонить» (callback `rb:a:<id>` / `rb:r:<id>`); решение обновляет карточку и пишет запросившему. Одобрение — право `receipts_beta`: работают пробные `RECEIPTS_GROUP_TRIAL_MONTHLY` разборов и общий потолок. Команды владельца в личке: `/beta <код-приглашения>` — открыть доступ без запроса, `/requests` — список ожидающих запросов, `/grant` — снять лимит (и открыть доступ), `/revoke` — убрать оба права. Если `ADMIN_USER_IDS` пуст, запрос сохраняется, а в логах предупреждение.

**Лимиты и учёт** (`server/src/receipts/limits.ts`, #102). Группе без права `receipts` доступно `RECEIPTS_GROUP_TRIAL_MONTHLY` пробных сканов в календарный месяц (по времени сервера); право снимает этот лимит. Владелец (`ADMIN_USER_IDS`) выдаёт и отзывает право в личке с ботом: `/grant <код-приглашения> [дней]` и `/revoke <код-приглашения>`. Расход на все сканы ограничен общим месячным бюджетом: при 80% владелец получает сообщение, при 100% сканирование приостанавливается. На каждый скан в `receipt_scans` пишутся только группа, модель, токены и стоимость, без фото и содержимого чека.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `RECEIPTS_BETA` | `1` | закрытая бета: чеки доступны только одобренным группам; `0` — открыто всем (с пробным лимитом и общим потолком) |
| `RECEIPTS_GROUP_TRIAL_MONTHLY` | `5` | пробных сканов на группу в месяц, пока у группы нет права `receipts` |
| `RECEIPTS_USER_PER_MIN` | `3` | запросов распознавания на пользователя в минуту |
| `RECEIPTS_GLOBAL_MONTHLY_USD` | `10` | общий потолок расхода в месяц, $ |
| `RECEIPTS_PRICE_IN_USD_PER_M` | `0.1` (`0.15` для openrouter) | цена входных токенов, $ за 1 млн (для расчёта стоимости; одна на все модели, при каскаде другой моделью задайте под свою; значение по умолчанию для openrouter — Qwen3.5-35B-A3B) |
| `RECEIPTS_PRICE_OUT_USD_PER_M` | `0.5` (`1.0` для openrouter) | цена выходных токенов, $ за 1 млн |

Замер качества на своих фото (не коммитить): `OPENROUTER_API_KEY=… [RECEIPTS_REASONING=none] npx tsx scripts/receipts-bench.ts <папка> [--models a,b] [--reasoning none|minimal|low|medium|omit]` печатает долю чеков со сходящейся суммой, токены, задержку p50/p95 и цену за 1000 сканов.

Конфиденциальность: фото уходит выбранному провайдеру (Anthropic или через OpenRouter к хостеру модели) только на время запроса и у нас не хранится, позиции не сохраняются, учитывается лишь число сканов и стоимость; при «Удалить мои данные» согласие удаляется, а записи о сканах отвязываются от человека (остаются обезличенно как учёт расхода для месячного бюджета). Текст политики (`/privacy` и экран в приложении) и экрана согласия зависит от `RECEIPTS_PROVIDER`: называет того, кто получает фото, и пересказывает его правила хранения по официальной документации (для OpenRouter — запрос с `provider.data_collection: 'deny'`). Политика обещает, что в аккаунте OpenRouter выключены запись запросов и использование их для улучшения продукта (Settings → Privacy) — держите их выключенными. С `OPENROUTER_BASE_URL` на свой сервер текст про OpenRouter неверен — поправьте `shared/privacy.ts`. Перед включением функции или сменой провайдера в продакшене проверьте, что `shared/privacy.ts` (ru/en) отражает фактическое поведение. Подробности: `docs/specs/receipts.md`.

## Настройка бота в @BotFather

1. `/newbot` → токен в `BOT_TOKEN`.
2. `/newapp` → URL `https://kopeika.usov-home.ru`, short name → в `APP_SHORT_NAME`.
3. При старте сервер сам ставит кнопку меню бота, ведущую на `APP_URL`.
4. **Вручную:** `/mybots` → бот → Bot Settings → Privacy Policy → указать `https://<домен>/privacy`. Страница на двух языках отдаётся самим сервером (`?lang=en` — английская), внутри приложения та же политика открывается по `#/privacy`. Текст политики — `shared/privacy.ts`; менять его нужно вместе с кодом, если меняется то, что мы храним или показываем.

## Удаление данных пользователя

Кнопка «Удалить мои данные» на главном экране вызывает `DELETE /api/me` (код — `server/src/account.ts`, одна транзакция): группы, где пользователь единственный с Telegram, удаляются целиком; из остальных он выходит (становится участником без Telegram, владение передаётся); строка `users`, напоминания и токены привязки чатов удаляются; регулярные траты пользователя ставятся на паузу; трата, записи истории и шаблоны, которые он создал, переходят на служебного «удалённого пользователя» (`users.id = 0`). Из ежедневных бэкапов данные уйдут сами через `BACKUP_KEEP` дней.
