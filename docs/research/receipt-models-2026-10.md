# Замер vision-моделей OpenRouter для разбора чеков (17.10.2026)

Задача: #144. Здесь только выводы замера; рабочие скрипты в репозиторий не входят.

## Метод

- Боевой путь без изменений: `openrouterProvider.parseReceipt` + `normalizeReceipt`, тот же `SYSTEM_PROMPT` и strict-схема, `require_parameters: true`, `data_collection: 'deny'`.
- Набор: 17 синтетических чеков (HTML → JPEG через Playwright, до 2000 px, качество 0,8 как в `web/src/receiptPhoto.ts`) и один не-чек. Российские супермаркеты (20 и 22 строки), кафе, кофейня; валюты GEL, TRY, EUR, USD, THB; длинный чек (42 строки); блёклый, поворот −6°, размытие, перспектива, мятый, на столе; рукописный счёт.
- Только open-weight модели у сторонних хостеров: проприетарные API OpenAI, Google и Anthropic исключены из-за региональных правил.
- Расход замера: $0,87. Метрика «sum ok» — доля чеков, где позиции сходятся с напечатанным итогом после нашей нормализации.

## Каскад

Первая ступень Qwen3.5-35B с `none`; вторая запускается, только если сумма не сошлась (3 чека из 17). Симуляция:

| Вторая ступень | Строки и итог верно | $ за 1000 в среднем |
|---|---|---|
| нет | 82 % | 1,12 |
| Qwen3.5-35B `low` | 100 % | 1,81 |
| Qwen3.6-35B `low` | 94 % | 1,59 |

Поэтому по умолчанию для openrouter вторая ступень — та же модель с `low` (`RECEIPTS_FALLBACK_REASONING`).

## Подводные камни

1. `reasoning: { effort: 'low' }` вместе с `require_parameters: true` даёт HTTP 404 «No endpoints found» у моделей, у которых `reasoning` нет в `supported_parameters` (Gemma 3, Mistral Small 3.2, Qwen3-VL-30B, Llama 4 Maverick). Для них поле нужно не отправлять вовсе: `RECEIPTS_REASONING=omit`.
2. Без рассуждений модель иногда пишет «в т.ч. НДС 20 %» как отдельную добавку (промпт это запрещает), и сумма не сходится. `low` это лечит, отсюда каскад.
3. `none` принимают не все хостеры: у Qwen3.5-35B принимают Venice и DeepInfra.
4. Таймаут 30 с режет хвост (p95 22–33 с), поэтому для openrouter он теперь 45 с.
5. Модель копирует знак валюты вместе с суммой («฿1,815.00», «$82.93», «*4.174,50»), и `parseDecimal` раньше возвращал `null`, из-за чего терялся итог (точный итог у Qwen3.5 на DeepInfra: 82 % со знаком против 100 % без). Исправлено в этой задаче.

## Рекомендуемые значения

Эти значения теперь стоят по умолчанию для `RECEIPTS_PROVIDER=openrouter`:

```
RECEIPTS_PROVIDER=openrouter
RECEIPTS_MODEL=qwen/qwen3.5-35b-a3b
RECEIPTS_REASONING=none
RECEIPTS_FALLBACK_REASONING=low
RECEIPTS_PRICE_IN_USD_PER_M=0.15
RECEIPTS_PRICE_OUT_USD_PER_M=1.0
RECEIPTS_TIMEOUT_SEC=45
# OPENROUTER_PROVIDERS=venice  (необязательно)
```
