# Копейка — заметки для агентов

Telegram Mini App для учёта общих трат в компании: группы, траты (поровну / долями / суммами), балансы, план переводов, приглашения по ссылке, уведомления от бота. Интерфейс на двух языках: русском (основной) и английском.

## Устройство

```
web/      Mini App: React + Vite + TS. Без роутер-библиотек и UI-китов.
  src/tg.tsx       обёртка над telegram-web-app.js: MainButton, BackButton, haptic, диалоги, dev-режим
  src/router.ts    hash-роутер; у каждого экрана есть «родитель» для кнопки «Назад»
  src/api.ts       клиент API + кэш групп (useGroup / setGroup)
  src/pages/       экраны; src/ui.tsx — общие компоненты; src/styles.css — стили на переменных темы Telegram
server/   Node + Hono, собирается esbuild в один файл
  src/api.ts       все эндпоинты /api, авторизация, валидация zod
  src/repo.ts      чтение данных и сборка ответов (groupDetail, groupsForUser)
  src/db.ts        node:sqlite, миграции списком
  src/bot.ts       grammY (long polling), /start, уведомления
  src/auth.ts      проверка подписи Telegram initData
shared/i18n/      словари ru/en, `t`, `pickLang` — общие для сервера и фронта
shared/money.ts    деление сумм, балансы, план переводов, парсинг и формат денег — общий для сервера и фронта
```

## Команды

```bash
npm install
npm test             # node:test через tsx: shared/*.test.ts, server/src/*.test.ts
npm run typecheck    # tsc для server и web
npm run check        # Biome (линт + формат) + typecheck + test — то же, что гоняет CI
npm run format       # Biome: автоформатирование
npm run build        # web/dist + server/dist/index.js
npm run e2e          # Playwright (Chromium): сам собирает, поднимает сервер с DEV_AUTH и гоняет основной сценарий
npm run dev:server   # API :3000 (читает ../.env)
npm run dev:web      # Vite :5173, проксирует /api
```

Проверка в браузере без Telegram: собрать, запустить
`DEV_AUTH=1 BOT_POLLING=0 DB_PATH=data/dev.db node server/dist/index.js`
и открыть `http://localhost:3000/?dev=1`. Второй пользователь — `?dev=2`, приглашение — `?dev=2&startapp=<inviteCode>`. Нижняя кнопка Telegram вне Telegram рисуется как обычная `.main-button`. Проверять в мобильном размере (375×812).

## Правила

- **Деньги — целые числа в минимальных единицах** (копейки, центы). Никаких float в расчётах. Деление и округление — только через `shared/money.ts`; сумма долей всегда равна сумме траты.
- **Миграции только дописываются** в конец списка в `server/src/db.ts`. Существующие не менять.
- **Не ослаблять авторизацию.** Каждый эндпоинт группы проверяет членство (`loadGroupFor`). `DEV_AUTH` — только для локальной разработки и тестов.
- **Приложение не проводит платежи и не хранит чужие деньги** — только показывает реквизиты и отмечает переводы.
- **Два языка — русский и английский.** Любой текст, который видит пользователь (интерфейс, сообщения бота, ошибки API), добавляется сразу на обоих языках через словари i18n, а не строкой в коде. Язык берётся из `language_code` пользователя Telegram: `ru` → русский, остальные → английский. Словари — `shared/i18n/ru.ts` (источник правды) и `en.ts` (тот же набор ключей, иначе ошибка компиляции); в вебе — `t('ключ', {параметры})` из `web/src/i18n.ts`, на сервере — `createT(lang)`. Множественное число — объект `{ one, few, many }` и параметр `count`. Dev-режим: `?lang=en` (веб) и заголовок `X-Lang` (API).
- Тексты — коротко, по-человечески, без канцелярита. Ошибки API — `{ "error": "<понятный текст на языке пользователя>" }`.
- Цвета — только через переменные темы Telegram (`--tg-theme-*` и производные в `styles.css`), чтобы работали светлая и тёмная темы.
- Новые зависимости — только если без них заметно сложнее; во фронте следить за размером бандла.
- **Тесты не трогают `data/kopeika.db`:** тест, который (даже косвенно) импортирует `db.ts`, первым импортом берёт `./test-env.ts` (или сам задаёт `DB_PATH` до динамического импорта); без `DB_PATH` под `node --test` `db.ts` падает с ошибкой.
- Поведение API покрывать тестами; новый баг — сначала тест, который его ловит.

## Процесс

- Задачи — GitHub Issues с этапами (milestones). Формат задачи: Зачем / Что сделать / Где в коде / Вне рамок / Готово, когда. Метка `agent-ready` — задачу можно брать без уточнений; `needs-info` — сначала нужен человек.
- Одна задача — одна ветка (`feat/…`, `fix/…`, `chore/…`) и один PR с `Closes #N`. В `main` напрямую не пушить: он защищён, слияние — squash после зелёного CI.
- CI (`.github/workflows/docker.yml`): `npm run check` (Biome + typecheck + тесты), затем сборка образа. Пуш в `main` публикует `ghcr.io/web-usov/kopeika:latest` — это продакшен.
- Перед PR: `npm run check`; если менялся UI — проверить в браузере по инструкции выше.

## Версии и релизы

- Версия — это git: `git describe --tags --always` (`v0.1.0` на теге, `v0.1.0-3-gabc1234` между релизами). Вручную номер нигде не поднимается; без тегов и вне CI версия `dev`.
- Этап (milestone) = минорная версия: v0.1 «Фундамент», v0.2 «Повседневное» и т.д. Задачи привязываются к этапу-версии через milestone.
- Когда этап закрыт — GitHub Release с тегом `vX.Y.0` и автоматическими заметками (Generate release notes).
- Срочные исправления — патч-релиз `vX.Y.Z`.
- Версия видна в подвале главного экрана, в логе старта сервера, в `GET /version` (`{ version, sha }`) и в метке образа `org.opencontainers.image.version`. CI передаёт её в сборку как build-arg `APP_VERSION` / `GIT_SHA`.
